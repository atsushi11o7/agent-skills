# kaggle-competitions-submit

提出は1日あたりの回数制限があり、一度送ると取り消せない。無駄な提出をしないよう、投稿前の確認を丁寧に行う。

## 手順

1. **コンペティションを決める**

   AGENTS.md（またはCLAUDE.md）にKaggleコンペティションのslug（例: `titanic`）が指定されていれば、それを使う。指定がなければユーザーに聞く。憶測しない。

2. **提出ファイルを確認する**

   ユーザーが指定したパスの提出ファイル（CSV）を使う。指定がなければユーザーに聞く。ディレクトリ内を探して勝手に候補を選ばない。ファイルが実際に存在するか確認する。

3. **提出ファイルが要件に合っているか確認する**

   コンペティションによって提出形式の要件（ファイル形式、列構成、命名規則など）は異なるので、一律には決めつけない。コンペティションのOverview/Rulesページに記載されている提出要件を確認し、それに沿っているか確認する。判断がつかない、または要件が読み取れない場合はユーザーに確認する。

   加えて、コンペティションのデータに`sample_submission.csv`が含まれている場合は、列名・列数・行数を提出ファイルと機械的に比較できる。一致しない場合は差分をユーザーに提示し、続行するか確認する（提出回数を無駄にしないため）。

4. **その日の提出回数を確認する**

   ```bash
   kaggle competitions submissions -c <competition>
   ```

   タイムスタンプが今日のものを数える。コンペティションの1日あたりの上限に近い、または達している場合はユーザーに警告し、続行するか確認する。

5. **提出メッセージを下書きする**

   `git-commit`スキルと同じ考え方で、会話や直近の変更（モデルの変更点、パラメータ、CVスコアなど）から下書きを作る。実際に確認していない情報（計測していないスコアなど）を捏造しない。

6. **確認してから投稿する**

   コンペティション名・提出ファイル・メッセージをユーザーに見せる。OKが出たら:

   ```bash
   kaggle competitions submit -c <competition> -f <file> -m "<message>"
   ```

7. **送信したら報告して終了する**

   スコアがつくまで待たない（時間がかかることがあるため）。送信が完了したことを報告し、スコアは`kaggle competitions submissions -c <competition>`で後から確認できる旨を伝える。

## 注意

- 提出は取り消せず、回数制限もあるので、確認なしに投稿しない。
- CVスコアやモデルの性能を捏造しない。実際に確認したことだけを下書きに書く。
